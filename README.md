- 核心功能：
  - **「判断训练」系统（本版核心）**：顶部 Tab「教学训练 / 自由沙盘 / 动画实验室」切换。教学训练由 8 章必修 + 3 章选学组成，每章统一走「观察 → 判断 → 承诺理由+信心 → 看模拟结果 → 复盘归因 → 提炼一条个人规则」六步经验循环；不是只教概念公式，而是训练「怎样形成判断、怎样从错误中积累经验」。
  - **Forecast 经验本**（localStorage，key `sku_forecast_journal_v1`）：首页展示已完成循环数、高估 / 低估 / 较准确次数、最常犯错根因；同一章重做会覆盖旧记录，留下成长轨迹。
  - **四维度评分**：数据观察 / 逻辑依据 / 数值偏差 / 信心校准，不是只看对错。
  - **沙盘解锁**：完成 ≥ 3 次完整经验循环才解锁「自由沙盘」（原模拟器），否则显示遮罩与还需几次的提示。
  - 自由沙盘：**五个真实场景预设**（EU 稳定 / UK 黑五 / 新品首单 / EOL 清库 / 促销防守）、参数调整、180 天库存模拟、经营诊断、时间轴、库存曲线、四个快捷动作；「真实备货公式」面板（平均日销 / 当天备货量 / 红绿线 / 补货触发日，对齐《销售预测培训》）。
  - **🎬 动画实验室（v0.6 新增 / v0.7 重做为「搭积木式」/ v0.8 重做为「看图说话」）**：把 Forecast 理论做成可视化动画。**关键改进 v0.8：从 0 教起——先认坐标系，再教斜线/竖线/虚线/面积分别代表什么**。不再只丢一句"库存是一堆货"，而是像 MathLab 教学一样，每个元素都解释「为啥用这个几何形状」「为啥会动」「代表什么」。侧栏加**「📖 看图词典」**面板，随关卡逐步累计 14+ 条术语（📐 坐标图 / ━ 横线 / 📉 斜线 / 🔺 三角形 / ▨ 绿色填充 / ▏ 红竖线 / 📅 覆盖天数 / 🕹 下单日 / 🔻 绿箭头 / 🟥 红缺货区 / 📍 参考建议线 / 🟣 紫虚线 / 🟡 尖峰）。时间轴改中文「第 N 天/今天/60 天后」，加 y 轴刻度。7 关顺序 = 📦 库存本体 → 📉 每日卖出 → 🔴 售罄日 → 🟢 补货到货(下单日=玩家决策，提前期=物流方式选择) → 🟠 参考建议线(安全库存几档缓冲) → 🟣 你的预测线 → 🟡 促销尖峰；每关只高亮【新滑块】、告诉你从哪拖到哪、看什么，还有「看演示」自动帮你拖一遍。**v0.14 起「哪天下单」改成玩家直接拖动决策，「补货提前期」改成物流方式按钮选择，「安全库存天数」改成几档参考建议线（不再自动帮你下单）**。
  - **v0.5 经营进阶面板（本版新增，对齐 Govee 真实指标体系）**：
    - **GMV 拆解**：GMV = CR × AOV × Session；AOV = 单价 × 连单率；Session 拆成 Paid（Google/FB/AFF/Bing）+ Free（Organic/Direct）六路流量占比可视化。
    - **成本结构（指标逻辑五口子）**：采购价/GMV、头程（多海运少空运）、尾程（派等单）、营销（AS 控 ROI）、其它（仓储/平台/风控/关税）、收单，按 GMV 占比估算，与贡献利润并列交叉验证。
    - **ROI 与复购**：ROI = 销售额 ÷ 广告花费（广告承压该涨就涨、但要盯 ROI，对齐攻略 P6）；复购率 = 积分/EDM/售后流量贡献的长期 GMV。
    - **综合经营评分**：GMV 25% + 贡献利润 25% + 库存健康 20% + 缺货控制 15% + Forecast 准确 10% + 价格健康 5%（handoff 第 13 节公式），六维加权得分 + 总评颜色分级。
  - 教学章节（v0.5 已全面真实化）：8 章必修 + 3 章选学全部嵌入 Govee 真实方法论与引用锚点（forecast 攻略 P1–P8、业务逻辑.jpg、指标逻辑.jpg），从“教概念”升级为“教判断依据”。
- 交互增强：浅 / 深色主题切换（CSS 变量 + localStorage 记忆）、Material 风卡片与 KPI 网格、状态 pill、触控友好（最小点击目标 44px）、底部固定「重新模拟」按钮（移动端）

## GitHub 同步约定

远程仓库：

```text
https://github.com/Chris-zidi/sku-simulator-mvp
```

本项目采用“完成即同步”的默认规则：

1. 每次开发开始前先同步远程最新代码。
2. 每次完成一个可独立说明的改动后，先验证，再提交 Git。
3. 提交后默认推送到 GitHub，不需要项目负责人重复提醒。
4. 每次提交都要更新 `DEVELOPMENT_LOG.md`，记录版本、变更、验证结果和遗留问题。
5. 不提交未验证的半成品；跨电脑继续开发前，先确认本地分支与远程一致。

常用命令：

```bash
git pull --rebase
git status
git add <本次相关文件>
git commit -m "简明描述本次改动"
git push
```

## 版本管理

项目使用语义化版本：

```text
主版本.次版本.修订版本
MAJOR.MINOR.PATCH
```

- `PATCH`：修复、文案、样式微调和不改变产品范围的小改动。
- `MINOR`：向后兼容的新功能、新关卡或明显的模型能力提升。
- `MAJOR`：不兼容的架构、数据或核心玩法升级。

## 已确认的接手风险

1. 模拟循环使用 `day <= 180`，实际会计算第 0 天到第 180 天，共 181 个日周期；页面和文档描述为 180 天，需要统一时间口径。
2. 没有发生库存耗尽时，`physicalStockoutDay` 默认返回第 180 天，时间轴仍显示“库存耗尽”，可能误导用户。
3. “稳定款”期末库存约 54 件、覆盖约 2 天，但 `overstock` 规则仍将其判为积压风险，诊断文案与期末库存状态矛盾。**（v0.2.0 已缓解：积压判定改为期末覆盖 > 120 天，稳定款不再误判。）**
4. 库存曲线中的到货线没有对超过 180 天的 Lead Time 做贴边或隐藏处理，可能绘制到 SVG 画布之外。
5. 缺货区间宽度按首尾缺货日之差计算，单日缺货时宽度为 0；若缺货被到货暂时打断，连续区间也会被合并成一个长区间。
6. 核心模拟、诊断和 DOM 渲染全部耦合在一个 HTML 文件中，当前无法直接对业务函数建立稳定的单元测试。
7. 输入依赖浏览器控件的 `min`/`max`，模拟函数本身没有处理 `NaN`、负数或越界值。
